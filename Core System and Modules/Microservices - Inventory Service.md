# Microservices - Inventory Service

## Deskripsi

_Inventory Service adalah microservice untuk manajemen **aset/inventaris General Affairs (GA)** — mengelola item peralatan beserta spesifikasi, pemegang (heldBy), dokumen pembelian/kedatangan, serta riwayat perbaikan/maintenance. Fokusnya adalah pelacakan **aset** (asset tracking), bukan stok-kuantitas gudang._

- **Stack:** Go + Fiber v2 + MongoDB + MinIO
- **Path:** `services/inventory`
- **Status**: ⚠️ Implemented (ada catatan): aset, repair, dan reporting lengkap; **Booking Ruang GA** irisan 1 dari 7 di kode (backend + layar web); irisan 1b (aksi web) merged dan di prod 2026-09-15; irisan 2 (MyBharata, riwayat terstruktur) merged 2026-09-15, belum di PROD maupun store

Aksi booking lewat web (irisan 1b) sudah di prod sejak 2026-09-15, jadi sampai MyBharata terbit pemohon dan penyetuju bekerja lewat web.
  - **Booking berulang** (harian atau mingguan): direncanakan irisan 3. Hari ini satu dokumen `ga_peminjaman` = satu tanggal.
  - **Pemilih ruang kantor di modul lain** (Agenda Kalender, Interview dan Onboarding review, Program Culture, Pelatihan): direncanakan irisan 4 sampai 7. Field `asal{modul, id}` sudah ada di model dan sudah dilewati feed kalender, tetapi belum diisi jalur mana pun.
  - **Kendaraan dan barang**: ditunda. Field `jenis` disiapkan, kodenya sengaja belum digeneralisasi.
  - **Dua perubahan isian yang bersamaan saling timpa** (yang terakhir menang): penjaga penulisan hanya mengunci status dan jadwal, bukan `keperluan`/`no_wa`/`keterangan`.
  - **`ga.view` membuka data pribadi pemohon**: jadwal seluruh booking memuat nama, divisi, keperluan, dan nomor WhatsApp (tertulis di deskripsi izin dan paket di `shared-library/common/catalog_ga.go`). Lihat [[CORE - RBAC dan Permission Set]].
  - **Riwayat lama** (sebelum irisan 2) masih menyimpan kalimat Bahasa Indonesia buatan server di `alasan` (mis. `Jadwal sebelumnya: ...`, `Jadwal sudah disetujui untuk booking ...`); tak ada migrasi, klien menampilkannya sebagai cadangan. Riwayat baru terstruktur (lihat di atas) sejak #1899 merged 2026-09-15, belum di PROD.
- **Kategori & nama barang bebas-ketik**: frontend kini memakai input teks manual (dropdown/saran dihapus). Backend tetap mendaftarkan kategori ke koleksi `category` via `resolveCategory` saat create, sehingga koleksi & endpoint `/categories` kini **vestigial** untuk UI (masih terisi, tidak lagi dibaca dropdown). Nama & kategori disimpan **apa adanya** (trim + rapikan spasi), dedup master **case-insensitive**; hanya **ID** yang di-UPPERCASE.
- **Integritas dokumen (anti `NoSuchKey`)**: `CreateInventory`/`UpdateInventory` memanggil `ValidateDocumentsExists` (MinIO `StatObject`) → tolak `400` bila objek tidak ada, mencegah referensi menggantung. `GeneratePresignedURL` membersihkan nama objek (`sanitizeObjectName`). Catatan operasional: presigned di-sign untuk `MINIO_PUBLIC_BASE_URL`; jika app HTTPS sementara nilai ini HTTP → upload diblokir *mixed-content* (perbaiki di infra, bukan kode).
- **ID pakai WIB**: komponen tanggal ID dibaca `time.FixedZone("WIB", +7)` agar tidak mundur 1 hari dari tanggal yang tampil (frontend kirim ISO UTC).
- **Penomoran ID: `MAX + 1`, bukan `count + 1`** (⚠️ branch `feat/inventory-fix-dup-id`, belum merge). `generateUniqueID` dulu memakai `count(prefix)+1`. Begitu ada **lubang** (item ber-prefix sama pernah **di-hard-delete**), `count < nomor tertinggi`, sehingga `count+1` menabrak `_id` yang masih ada → `InsertOne` gagal **E11000** dan aset baru **tak bisa disimpan** (terjadi nyata: `INV-BIP-120525-MEJAKANTORCUSTOM-25`). Bukan menimpa data — insert ditolak, data lama aman. Perbaikan: (1) `nextSeqInventoryID` (fungsi murni) ambil **nomor urut tertinggi** dari `_id` berprefix + 1 — `_id` string, jadi angka ekor diparse di Go (sort leksikal salah), pakai `regexp.QuoteMeta`; (2) `insertInventoryWithRetry` + `retryOnDup` meng-generate ulang & mengulang saat `mongo.IsDuplicateKeyError` (maks 5x) untuk balapan create paralel. **Kedua** jalur create (`CreateInventory` & `aset_dari_pengajuan`) lewat helper ini. Penomoran **tidak** menyaring `deleted_at`: dokumen yang di-soft-delete tetap ikut dihitung supaya nomornya tak dipakai ulang (menghindari tabrakan `_id` dengan sisa soft-delete). Format `_id` sendiri **tak berubah**.
- **Serah-terima aset (`HeldBy`)**: alur = **Serahkan/Ubah Pemegang** (GA, via `PATCH /item/:id`) → `handover_status=menunggu_spv`, rekam penyerah (`handover_by`) & departemen penyerah (`handover_dept`) → **SPV penaung menyetujui** (`PATCH /item/:id/approve-handover`) → rekam `known_by_spv` + `handover_status=disetujui`. **Tarik/Kembalikan** = kosongkan pemegang + set `revoked_at` → "Tersedia di GA". Catatan pengganti tanda tangan surat serah terima = **`handover_document`** (upload, menggantikan catatan teks lama `handover_notes` yang kini deprecated).
- **Lokasi & penyusutan**: `InventoryItem` + `location` (string) & `useful_life_years` (opsional). **Nilai buku & penyusutan/tahun TIDAK disimpan** — dihitung di **frontend** (garis lurus, residu 0) sebagai *estimasi operasional GA*, bukan angka pembukuan (akuntansi via Accurate, lihat [[ADR - 0001 Akuntansi via Accurate]]).
- **Export**: daftar aset diekspor ke Excel **client-side** (frontend, `lib/export.ts`/exceljs) dari data `GET /items` yang terfilter — tak ada endpoint export di service.
- **Rekonsiliasi aset ↔ Accurate (ADR-0037; §pencocokan & skor sejak 2026-08-22 di-supersede [[ADR - 0049 Padanan Aset per-item berbasis nama menggantikan kategori-golongan]])**: `InventoryItem` + `accurate_asset_no` & `reconciled_at`. **Komputasi 100% di frontend** — alur ini **tak memanggil service lain**: FE mengomposisi `GET /items` (inventory) + `GET /accounting/fixed-assets` ([[Microservices - Integration Service]]), memasangkan barang ERP ↔ aset Accurate **berbasis NAMA** (nama Accurate kini dari field `description`, [[Microservices - Integration Service]]) & menyimpan pasangan lewat `PATCH /item/:id` (`accurate_asset_no`). Padanan dilakukan di **dua layar yang menulis kunci sama**: **Pengaturan Aset** (editor padanan langsung barang→aset, pengganti editor kategori→golongan) dan tab **Cocokkan** (saran by nama + tandai ⚠ padanan lama yang salah + tombol Ganti). Skor akurasi/cakupan (ERP-only=100%) kini menilai **kesamaan DATA: harga + tanggal, TANPA golongan** (ADR-0049 §4). Koleksi `asset_category_mapping` jadi vestigial (lihat baris **Pemetaan kategori → golongan** di atas). **Feed KPI (Fase 2) belum** — dan saat rilis wajib membuang golongan sesuai ADR-0049.

## Dependencies & Integrasi

- **MongoDB** — collection: `inventory`, `data_master`, `repair_history`, `category`, `asset_category_mapping`. `inventory` kini punya tanda soft-delete `deleted_at` (`*time.Time`, omitempty) + `deleted_by` + `delete_reason` — KOSONG untuk aset hidup; keberadaan `deleted_at` = tanda terhapus (branch `feat/aset-soft-delete`).
- **MinIO** — diakses langsung untuk presigned URL serta upload image/PDF (limit 4MB); objek diverifikasi ada sebelum referensinya disimpan. Lihat [[Microservices - File Service]].
- Diekspos via gateway — lihat [[CORE - API Master Gateway]].
- Skema database — lihat [[DB - Overview and Notes]].
- **MongoDB (Booking Ruang)**: `ga_ruang`, `ga_peminjaman`, `ga_peminjaman_penyetuju` (nama koleksi di `shared-library/models/inventory/models.go`). Mongo inventory standalone, sebab itu persetujuan memakai kunci sewa per ruang, bukan transaksi.
- **[[Microservices - Employee Service]]** (env `EMPLOYEE_MODULE_URL`). Dua panggilan, keduanya membawa kunci gateway di header `BIP-Gateway-ID` (nilai `INTERNAL_GATEWAY_KEY`) dan meneruskan header identitas pemanggil (daftar `headerIdentitasDiteruskan` di `peminjaman_penyetuju.go`):
  - `GET /list?type=employee[&company=]` untuk memvalidasi penunjukan penyetuju Booking Ruang. Respons dibaca sebagai array telanjang; bentuk lain ditolak sebagai galat, bukan dibaca sebagai daftar kosong. `company` hanya dikirim bila berbeda dari perusahaan pemanggil.
  - `GET /internal/department-approver?department=&company_id=` untuk mencari SPV penerima notifikasi Permintaan Barang GA (`atasanDepartemenLewatEmployee` di `permintaan_notify.go`). Klien ini dulu memakai header `key` tanpa identitas, sehingga notifikasi SPV tak pernah terkirim; kini memakai header yang sama dengan panggilan di atas (dikunci `TestAtasanDepartemenMeneruskanGatewayDanIdentitas`). Jawaban non-2xx dibaca sebagai "tak ada penerima" dan hanya dicatat log.
- **[[Microservices - Notification Service]]** (env `NOTIFICATION_MODULE_URL`, `NOTIFICATION_SERVICE_KEY`, `INTERNAL_GATEWAY_KEY`): `POST /inbox/send?key=` lewat `kirimInbox`, dipakai Booking Ruang dan Permintaan Barang GA, best-effort. Kiriman membawa header `BIP-Gateway-ID`, karena notification-service memasang `ValidateGateway` untuk seluruh rutenya dan kunci layanan di query tidak menggantikannya. ⚠️ Sampai 2026-09-14 header itu tak pernah dikirim (sejak `kirimInboxPermintaan` lahir 2026-08-27), jadi setiap kiriman dibalas 401 `Unauthorized gateway` dan hanya tercatat di log: notifikasi inbox Permintaan Barang GA tak pernah sampai. Ditemukan saat verifikasi lewat gateway dev, dikunci `TestKirimInboxMenembusGerbangNotification`. Kategori `peminjaman-ga-*` wajib ada di salinan `notification.InboxCategories` milik kedua container, jadi inventory-service dan notification-service naik bersama ([[RUN - Deploy Microservices bip-erp]]).
- **[[Microservices - Calendar Service]]**: memanggil feed `GET /internal/calendar-feed` service ini sebagai provider `inventory` (label "Booking Ruang", `services/calendar/providers.go`) lewat env `INVENTORY_MODULE_URL` di blok `calendar-service` `docker-compose.yml`. Env kosong membuat provider dilewati diam-diam.
- **Env compose `inventory-service`** (`docker-compose.yml` dan `docker-compose.dev.yml`): `EMPLOYEE_MODULE_URL`, `NOTIFICATION_MODULE_URL`, `NOTIFICATION_SERVICE_KEY` dicantumkan eksplisit, tak lagi bergantung pada isi `.env`. Env dibaca saat container dibuat, jadi perubahan env menuntut `--force-recreate`. Kill-switch izin `GA_PERMISSION_ENFORCEMENT=off` mengembalikan gerbang `ga.view`/`ga.work` ke `RequireGeneralAffair`.
- **Konsumen Booking Ruang**: [[APP - Web ERP]] (halaman Ruang & Booking, penunjukan penyetuju). Irisan 2 (merged 2026-09-15, belum di PROD): [[APP - MyBharata]] memakai ruang, slot, ajukan, detail, ubah, batal, setujui, tolak, dan `penyetuju/saya`; [[Microservices - Attendance Service]] membaca `/peminjaman/saya` dan `/peminjaman/perlu-aksi` untuk daftar pengajuan terpadu dengan `BIP-Gateway-ID` dan identitas pemanggil (403 perlu-aksi = bukan penyetuju).
